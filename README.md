# xmpp-server-guides

[English version](README.en.md)

Инструкции по установке и настройке XMPP-серверов на Ubuntu LTS.

Репозиторий собирает практические руководства по развертыванию XMPP-серверов в связке с reverse proxy, панелями управления и другой инфраструктурой. Каждая инструкция - отдельный markdown-файл, проверенный на конкретной версии ОС и конкретных версиях пакетов.

Инструкции рассчитаны на VPS в России. Поэтому в них есть проверки доступности зеркал APT, репозитория Prosody, Let's Encrypt и API Cloudflare, а также запасные варианты на случай, если что-то из этого недоступно из сети хостера. На VPS в других странах эти проверки проходят, остальная настройка не меняется.

Английские версии лежат рядом, в файлах с суффиксом `.en.md`.

### Какую выбрать

- **На VPS работает 3x-ui.** Инструкция для Ubuntu 22.04 с 3x-ui. Конфигурация 3x-ui не меняется: Prosody принимает клиентов на порту 5222, другие серверы - на 5269, обмен файлами работает по HTTPS на 5281. В приложении А описано, как принимать XMPP и файлы через порт 443 рядом с REALITY: Xray передает в HAProxy соединения, которые не прошли проверку REALITY, а HAProxy направляет их по SNI без расшифровки.
- **Отдельный сервер.** Инструкция для Ubuntu 24.04 или 26.04, по версии ОС. Prosody сам занимает порт 443: на нем работают и подключение клиентов (прямой TLS, XEP-0368), и HTTPS для обмена файлами. Данные хранятся в SQLite. Добавлена базовая подготовка сервера: пользователь с sudo, вход только по SSH-ключу, ufw. Инструкция для 26.04 отличается от 24.04 в нескольких местах: репозиторий Prosody подключается вручную, время синхронизирует chrony вместо systemd-timesyncd, sudo реализован как sudo-rs.
- **Отдельный сервер на Ubuntu 22.04.** Инструкции для чистого VPS на 22.04 не работают: драйвер `lua-dbi-sqlite3` там собран только для Lua 5.1-5.3, а Prosody 13 работает на Lua 5.4. Используйте инструкцию с 3x-ui, в ней стандартное хранилище Prosody, и пропустите шаги для 3x-ui и Xray.

## Что получается в итоге

Возможности сервера во всех инструкциях одинаковые, различаются схема портов и подготовка системы:

- Prosody 13 из официального репозитория packages.prosody.im;
- адреса вида `user@example.org`. Сайт на основном домене остается на прежнем хостинге (в примерах - GitHub Pages), клиенты и другие серверы находят XMPP-сервер через SRV-записи;
- wildcard-сертификат Let's Encrypt: выпуск через DNS-01 и API Cloudflare, автоматическое продление и импорт в Prosody;
- архив сообщений на сервере (MAM), обмен файлами, групповые чаты;
- звонки через coturn (STUN/TURN);
- модули для мобильных клиентов: восстановление сессии после смены сети, копии сообщений на все устройства, push-уведомления;
- закрытая регистрация: учетные записи создает администратор или они создаются по приглашению;
- обязательное шифрование для клиентов и серверов, проверка сертификатов других серверов;
- разделы про резервное копирование, обновления и устранение неполадок.

## Что понадобится

- VPS с нужной версией Ubuntu LTS и доступом по SSH.
- Домен, DNS которого обслуживает Cloudflare. С другим DNS-провайдером записи из раздела 3 создаются в его панели, а для выпуска сертификата в разделе 6 нужен соответствующий плагин certbot или ручная проверка DNS-01.
- Доступ к консоли VPS в панели хостера (VNC или аналог) на случай ошибки в настройке SSH или файрвола.
- XMPP-клиент. Клиенты для Android, iOS, macOS, Linux и Windows перечислены в разделе 10.2 каждой инструкции.

## Как читать инструкции

- В примерах используется домен `inkov.dev` и сервер `xmpp.inkov.dev`. Удобнее всего сделать копию инструкции со своим доменом:

  ```bash
  sed 's/inkov\.dev/example.org/g' GUIDE_XMPP_Prosody_Ubuntu_24.04.md > my-guide.md
  ```

  После замены проверьте имена учетных записей: список `admins` в конфигурации Prosody и примеры в разделе 10.1.
- Значения в угловых скобках (`<IP_VPS>`, `<EMAIL>`, `<CF_API_TOKEN>` и другие) нужно заменить своими. Их список с пояснениями есть в разделе 1.5 каждой инструкции.
- Команды выполняются на VPS, если не указано другое.
- После большинства шагов есть блок "Результат" с ожидаемым выводом. Если вывод отличается, не переходите к следующему шагу: сначала найдите причину. Таблица типичных ошибок есть в разделе 12.
- Для большинства шагов, которые меняют систему, приведены команды отката.

## Структура репозитория

Каждая инструкция - один файл, английская версия лежит рядом с суффиксом `.en.md`. Имена файлов строятся по схеме `GUIDE_<протокол>_<сервер>_<ОС>_<версия ОС>[_<дополнительный стек>].md`, новые инструкции добавляются по ней же.
